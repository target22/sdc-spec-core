# dlq_exceptions.log — Format Reference

Synthetic fixture. 5 entries, domain-neutral fields (`SDC-SPEC-INGRESS-v3.1.json`'s reference contract), generated by *actually running* the real encryption code path rather than hand-writing JSON — then round-tripped through the real read/decrypt parsing logic to confirm it's genuinely recoverable. Encrypted with a throwaway demo key, printed to stdout during generation, discarded — not your `DLQ_ENCRYPTION_KEY`.

## Line shape

```
2026-08-27 09:14:02,000 - ERROR - {...json...}
```

`%(asctime)s - %(levelname)s - %(message)s` — `engine/logging_setup.py`, the `Formatter` on `_dlq_handler`. `read_and_decrypt_dlq()` in `engine/dlq.py` recovers the JSON by `line.split(" - ", 2)[2]`, so the timestamp/level prefix can contain its own `" - "` sequences without breaking the parse (maxsplit=2 caps it at the first two).

## Entry shape

| Field | Source | Notes |
|---|---|---|
| `customer_id` | `dlq.py::dlq_log(customer_id, ...)` | plaintext by design — Directive II.3 encrypts *values*, not structural/routing metadata |
| `status_code` | `dlq.py::dlq_log(..., status_code, ...)` | plaintext; whatever HTTP status the caller passed |
| `reason` | `dlq.py::dlq_log(..., reason, ...)` | plaintext, built from static strings + field **names** only — `executor.py`'s `VALIDATE` handler deliberately never passes `e.message` here, since that can embed the raw failing value |
| `payload` | `security.py::sanitize_payload()` → `_encrypt_value()` | recursively walks the object; every leaf string/int/float becomes an encrypted blob, structure (dict/list shape) stays visible |

## Encrypted leaf shape

```json
{"type": "str", "len": 9, "fp": "fe7ab04d", "__enc__": "aesgcm", "n": "<12-byte nonce, b64>", "c": "<ciphertext, b64>"}
```

- `type` / `len` (strings only) / `fp` — `security.py::_encrypt_value`. `fp` is `_fingerprint()`: first 8 hex chars of `sha256(raw)`, correlation-only, not reversible by construction.
- `__enc__` / `n` / `c` — `security.py::_encrypt_str`. AES-256-GCM, fresh random 12-byte nonce per call, `associated_data=None`.
- `null` / `bool` values pass through unencrypted (`_encrypt_value`'s first branch) — no PII risk in those types, kept readable for debugging.
- Empty string `""` stays `""` rather than becoming an encrypted-empty-string blob (`_encrypt_value`'s explicit `if not value: return ""`).

## What each entry demonstrates

1. **422** — a `VALIDATE_BOUNDARY` schema failure (`step_2_validate`), payload present and nested (`fields` array, matches `security.py`'s `_encrypt_value` recursing through list + dict).
2. **400** — malformed-JSON-at-ingress path (`payload.py::_resolve_payload`); no payload to encrypt, since none was ever parsed.
3. **500** — a `DECISION_MATRIX` condition referencing an undefined variable (`executor.py`'s `MATRIX` handler / `condition_evaluator.py::ConditionError`), demonstrating a **re-submitted "Fat Payload"** shape (`trigger` + `db_check`, the Unified State Machine pattern from `classify`-stage contracts).
4. **200** — the `DLQ_REJECT` terminal-marker path (`executor.py::_execute_dag`) — status 200 because the DAG completed *successfully*, it just explicitly routed to rejection; not an error in the HTTP sense.
5. **404** — `contracts.py::_load_dag_contract`'s missing-contract-files path; no payload was ever loaded, so nothing to encrypt.
